# Native Noqeri → Zig link test and release status (19 October 2026)

This is a **real compilation-and-linking command**, not an acceptance report:

```
NOQERI_ROOT=/absolute/Noqeri \
NOQERI_COMMIT_SHA=<reviewed> \
NOQERI_SOURCE_CLOSURE_SHA256=<reviewed> \
NOQERI_NATIVE_COMPILER=/absolute/verified-noqeri \
NOQERI_NATIVE_COMPILER_SHA256=<sha256> \
npm run build:native-link
```

The command verifies source/compiler hashes and Stage-2 Noqeri proof, runs Zig 0.15.2 unit tests and builds the actual `libnoesql_zig_pages.a`, asks the **self-hosted Noqeri compiler** to emit Linux x64 assembly from `tests/noesql_zig_relational.nqr`, assembles using Clang, checks that the resulting object *defines* `noeZigRelationalSmoke`, links the object with the Zig page library and a small C test driver, and runs write + cold-process recovery/checkpoint checks. The C driver contains no relational execution implementation. It only calls the Noqeri-generated symbol and checks page/format integrity.

**Evidence status:** the C driver passed GCC `-std=c11 -Wall -Wextra -Werror -fsyntax-only` and the JavaScript build driver passed a syntax check. No real Noqeri-generated native object or Zig library has been built here. The current public Noqeri Stage-2 CLI does not implement the required `build <source.nqr> <output.s>` command, and the Noqeri bootstrap proof is unverified. The command therefore fails closed; it does not silently invoke the archived C++ compiler.

This test covers only the original bounded one-row integer/boolean Noqeri typed executor. It is **not** complete SQL parsing, catalog/index support, or the separate full-language `npm run qualify:native-e2e` requirement. Both are now required by `prepublishOnly`, along with platform and security qualification, before npm publishing can proceed.

**Publication still unavailable:** no npm authentication, trusted publisher registration, package-ownership proof, or public registry result was available in this environment. The npm package has not been uploaded. GitHub repository NoeSQL remains private; npm source provenance requires a public repo. Read `Doc/NOESQL_NPM_TRUSTED_PUBLISHING.md`.

## GitHub-hosted release artifact provisioning

The manual npm workflow now requires `native_artifact_run`, a reviewed GitHub Actions run that uploads an artifact named `noqeri-native-qualified`. It must contain `noqeri-stage0`, `noqeri-native-compiler`, `noesql-native` and a `noqeri-build/` directory containing `stage2-proof.json` plus both compiled/rebuilt Stage-2 files named inside that proof. The workflow checks out the pinned public Noqeri commit and copies only that explicitly named native toolchain artifact. A release variable containing an arbitrary filesystem path is no longer treated as proof.

The protected GitHub environment sets the approved SHA-256 hashes, source closure, and legal approval. The actual binaries and proof must be generated by a trusted native build process that is **not yet present**; any missing artifact causes a hard failure before publication. GitHub's unprotected PR build results must never be accepted as release artifacts without independent verification.
